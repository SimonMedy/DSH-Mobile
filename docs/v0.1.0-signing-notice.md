# Android v0.1.0 signing notice

**Applies to:** Android APKs distributed with the public `v0.1.0` GitHub Release.

## What happened

The `v0.1.0` release workflow built an APK using the repository's public debug keystore when no protected release key was supplied. A public signing key cannot establish a unique, trusted publisher identity. This does not mean that users' devices were remotely compromised, and there is no claim here that a malicious APK was distributed.

## What users should do

- Only obtain future DSH Mobile downloads from the official repository's Releases page. Avoid mirrors or update links sent by strangers.
- Do not install an APK solely because Android reports a matching application signature.
- Keep your DeepSeek Harness endpoint behind a trusted access layer; avoid exposing an unauthenticated developer environment publicly.
- Before migrating to a future differently signed version, record non-secret server configuration. Uninstalling the old app can erase device-local settings and browser sessions. Do not copy credentials, tokens or session cookies into notes or support reports.
- A future privately signed APK may require uninstalling v0.1.0 before installing, because Android normally rejects updates signed by an unrelated key. Follow the release notes for the exact migration procedure once a replacement is available.

## Maintainer status

The source release pipeline now refuses to build a public release APK when the private signing configuration is missing, verifies the output signer, and no longer publishes debug APKs alongside releases. These controls protect **future** releases only. Provisioning and protecting a permanent signing key remains necessary before the next public release. No APK was replaced or released as part of this notice.

See [release signing setup](release-signing.md) and [security policy](../SECURITY.md).
